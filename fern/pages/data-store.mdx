## About NeMo Data Store

NVIDIA NeMo Data Store manages the lifecycle of models and datasets in your projects. It simplifies the storage and retrieval of models, datasets, and evaluation results in your applications.

The NIM Operator deploys a NeMo Data Store as a Kubernetes custom resource, `nemodatastores.apps.nvidia.com`. A NeMo Data Store resource relies on a database and object store that are configured to hold model data.

Read the [NeMo Data Store documentation](https://docs.nvidia.com/nemo/microservices/25.8.0/manage-entities/index.html) for details on using a data store.

## Prerequisites

- All the common [NeMo microservice prerequisites](/nemo-prerequisites).

<Note>
You can use the [NeMo Dependencies Ansible Playbook](/nemo-prerequisites#deploy-nemo-dependencies-with-ansible) to deploy all the following NeMo Data Store microservice dependencies.

</Note>

**Storage**

- A [PostgreSQL](https://www.postgresql.org/docs/) database to store repository, branch, and LFS metadata. It can be externally provisioned or hosted in your cluster.
Refer to the [Helm installation guide](https://artifacthub.io/packages/helm/bitnami/postgresql) for more information on installing a PostgreSQL database.

**Kubernetes**

- Access to an NFS-backed Persistent Volume that supports `ReadWriteMany` access mode.
Stores Git history for models and datasets.

  You can create a PVC and specify the name when you create the NeMo Data Store resource
or you can request that the Operator creates the PVC.

- The NeMo Data Store relies on several Kubernetes secrets to manage model data.
The default secrets are created as part of NeMo Dependency Ansible playbooks, or you can apply the secrets file manually if you are deploying a NeMo Datastore as a separate component.

  Download the <Download src="_includes/downloads/nemo-datastore-default-secrets.yaml"><Button intent="primary">`NeMo Data Store default secrets file`</Button></Download>.

  ```console
  $ kubectl apply -f nemo-datastore-default-secrets.yaml -n nemo
  ```

- Create a secret for your database by creating a file called `nemo-datastore-secrets.yaml`, like the following example.

  <Code src="../../manifests/docs/current/input/nemo-datastore-secrets.yaml" language="yaml" startLine="1" />

  Apply the manifest:

  ```console
  $ kubectl apply -f nemo-datastore-secrets.yaml -n nemo
  ```

## Verify NeMo Data store

1. List the NeMo Data store services.

   ```console
   $ kubectl get services -n nemo
   ```

   *Example output*

   ```output
   nemodatastore-sample     ClusterIP   XX.XXX.XXX.XXX   <none>        8000/TCP               31m
   ```

1. Start a pod that has access to the `curl` command.
Substitute any pod that has the command and meets your organization’s security requirements:

   ```console
   $ kubectl run --rm -it -n default curl --image=curlimages/curl:latest -- ash
   ```

   After the pod starts, you are connected to the `ash` shell in the pod.

1. Verify NeMo Data Store.

   ```console
   curl -X GET "http://nemodatastore-sample.nemo:8000/v1/hf/api/datasets"
   ```
