## About Dynamic Resource Allocation (DRA)

[DRA](https://kubernetes.io/docs/concepts/scheduling-eviction/dynamic-resource-allocation/)
is a built-in Kubernetes feature that simplifies GPU allocation for NIMService, NIMPipelines, and NIMBuild.
It replaces traditional device plugins with a more flexible and unified approach.
It enables users to define GPU classes, request GPUs based on those classes,
and filter them according to specific workload and business requirements.
This extensibility makes DRA a powerful tool for managing GPU resources efficiently across diverse NIM use cases.

NIM Operator supports the
[NVIDIA DRA Driver for GPUs](https://github.com/NVIDIA/k8s-dra-driver-gpu)
and enables you to dynamically allocate GPU using a ResourceClaim or ResourceClaimTemplate.

NIM Operator supports DRA resource claims for two types of GPU usage:

- Full GPU

- Multi-Instance GPU (MIG)

Additionally, the supported GPU sharing strategies are:

- Time-slicing

<Note>
DRA support for NIM is currently a *Technology Preview* feature on NIM Operator,
which means it is not fully supported and is not suitable for deployment in production.

</Note>

### 1. Configure Prerequisites and Deploy DRA Driver for GPUs

- Ensure you are using Kubernetes v1.34 or later.
DRA is enabled by default in Kubernetes v1.34 and later.
The NIM Operator supports the DRA `apiVersion: resource.k8s.io/v1`.

- Configure the GPU Operator for DRA deployments using the [GPU Operator NVIDIA DRA Driver for GPUs deployment guide](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/dra-intro-install.html).

- If using DRA with MIGs, configure MIG Manager using
[GPU Operator with MIG deployment guide](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/gpu-operator-mig.html).

- Deploy the DRA driver helm chart with GPU DRA driver enabled.

  ```console
  $ helm repo add nvidia https://helm.ngc.nvidia.com/nvidia \
      && helm repo update
  ```

  ```console
  $ helm install nvidia-dra-driver-gpu nvidia/nvidia-dra-driver-gpu \
      --version="25.12.0" \
      --create-namespace \
      --namespace nvidia-dra-driver-gpu \
      --set gpuResourcesEnabledOverride=true \
      --set nvidiaDriverRoot=/run/nvidia/driver
  ```

Refer to the GPU Operator NVIDIA DRA Driver [installation documentation](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/dra-intro-install.html) for full details on install options.

<Note>
The NVIDIA DRA driver deploys a default device class `gpu.nvidia.com` for GPU resources.

Use the following command to view the device classes:

```console
$ kubectl get deviceclass

NAME             AGE
gpu.nvidia.com   78d
```

The `gpu.nvidia.com` DeviceClass represents physical NVIDIA GPUs managed by the NVIDIA GPU DRA driver.
You can use this DeviceClass to create ResourceClaim objects to request specific GPUs.

</Note>

### 2. Decide on GPU Usage: Full GPU or MIG

You must decide whether to use Full GPU or Multi-Instance GPU (MIG) for the GPU usage. Generally, Full GPU is used for LLMs, whereas time-slicing or MIG can be used for non-LLMs or smaller NIMs. Using MIG is a more advanced configuration.

If using MIG for the GPU usage, make sure you have enabled MIG and MIG Slicing. Refer to
[GPU Operator with MIG](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/gpu-operator-mig.html)
for more detailed instructions.

The GPU sharing strategy currently supported is time slicing.

GPU time-slicing enables workloads that are scheduled on oversubscribed GPUs to interleave with one another.
For more information, refer to [Time-Slicing GPUs in Kubernetes](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/gpu-sharing.html)

### 4. Configure NIM Service to Use the DRA Resource

There are two options for how NIM Service can use the DRA resource:

- [**Option A: Auto-generate ResourceClaimTemplate**](#option-a-auto-generate-resourceclaimtemplate) (recommended).
NIM Service automatically creates a ResourceClaimTemplate using the fields specified in `spec.draResources.claimCreationSpec`.

- [**Option B: Use pre-created ResourceClaim or ResourceClaimTemplate**](#option-b-use-pre-created-resourceclaim-or-resourceclaimtemplate).
First create a ResourceClaim or ResourceClaimTemplate, then configure NIM Service to use that ResourceClaim or ResourceClaimTemplate.

## Troubleshooting

This section explains some common troubleshooting steps to identify issues with DRA.

- Ensure that DRA is enabled in the cluster.

  ```console
  $ kubectl get deviceclasses
  ```

  The preceding command should not throw an error.

- Ensure that CDI is enabled and made the default runtime.

  ```console
  $ kubectl get clusterpolicy cluster-policy -o json | jq -r '.spec.cdi'
  ```

  Expected output:

  ```output
  {
    "default": true,
    "enabled": true
  }
  ```

- Ensure the NVIDIA DRA driver is functional and has 1 resourceslice per node from the `gpu.nvidia.com` driver.

  ```console
  $ kubectl get resourceslice
  ```

- Check the status of the ResourceClaim from the nimservice `status.draResourceStatuses` - it should be `allocated,reserved` if successful.

  ```console
  $ kubectl get resourceclaim <claim>
  ```

- Additionally, verify that the ResourceClaim has valid devices allocated.

  ```console
  $ kubectl get resourceclaim <claim> -o json | jq -r '.status.allocation.devices.results'
  ```

- If the NIMService pods are stuck in Pending/ContainerCreating state, you can describe the pod to get additional information.

  ```console
  $ kubectl describe pod <NIMService-Pod-Name>
  ```

- ResourceClaim allocation logs can be collected from the NVIDIA DRA driver.

  ```console
  $ kubectl logs -l app.kubernetes.io/name=dra-driver-gpu -n dra-driver -c gpus
  ```
